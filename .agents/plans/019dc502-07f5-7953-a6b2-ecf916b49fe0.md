## Summary

Add a generic root-cause implementation gate to Gold 5 as a hard cutover. The
hook must not preserve bare path-only `Allowed writes`. Implementation tasks
must use typed write authority entries so each target path has a behavioral
role. For `Kind: root-cause-change`, the active task must declare behavioral
authority: observed problem, required behavior, source of truth, canonical
owner, why it owns the behavior, rejected shortcuts, verification, and typed
allowed-write roles. The hook should mechanically block task-local forbidden
added patterns and obvious shortcut terms unless the plan explicitly justifies
them.
