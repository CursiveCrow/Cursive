## 0. Purpose

Build `CursiveOracle` as a Cursive-written conformance oracle for the Cursive compiler
and runtime.

The oracle is not a test-count runner, a `HelloCursive` replacement by import, an
audit-table consumer, a compiler trace label checker, or a set of manually expected
fixtures. Its job is:

```text
docs/CursiveSpecification.md
  -> structured spec document
  -> parsed formal model
  -> obligation graph
  -> executable reference semantics
  -> generated and curated conformance cases
  -> compiler/runtime execution
  -> reference-vs-implementation comparison
  -> obligation coverage report
```

The oracle is complete only when every normative obligation and formal semantic rule
in the spec is either:

```text
parsed
modeled
covered by reference semantics
tested against compiler/runtime behavior
passed
```

or explicitly classified as:

```text
blocked_by_current_compiler
blocked_by_oracle_language_support
outside_conformance
informative_only
spec_parse_error
reference_model_missing
implementation_failure
```

A global conformance pass is illegal while any required obligation is unparsed,
unmodeled, uncovered, blocked, unsupported, or failing.

## Current User-Directed Compiler Conformance Gate

Before continuing oracle implementation, resolve the compiler behavior exposed by the
first real oracle self-test: generic enum variant construction and matching.

Required actions:

1. Use `docs/CursiveSpecification.md` as source of truth for this construct.
2. Have a read-only subagent review the spec and compiler implementation.
3. Determine whether generic enum declarations plus `Enum::Variant(...)` literals
   under an expected `Enum<T>` type are required to work.
4. If required, fix the compiler at the canonical enum literal / enum pattern
   typing implementation, not by weakening or rewriting CursiveOracle.
5. Add a focused regression project that constructs and matches a generic enum
   variant through an explicitly declared generic enum type.
6. Rebuild the compiler and verify both the regression project and CursiveOracle.
7. Only then return to the oracle build sequence.

This gate is not a workaround and is not a scope reduction: compiler non-conformance
found by the oracle must be corrected in the compiler.

## 1. Non-Negotiable Rules

1. `docs/CursiveSpecification.md` is the only conformance source of truth.

2. The oracle must not read or depend on:

```text
docs/audit/**
SPEC_RULE_TABLE*
SPEC_IMPLEMENTATION*
HelloCursive expected output
compiler conformance trace labels
old audit exports
manual spreadsheet-derived rule maps
```

3. Expected compiler/runtime behavior must be derived through `ReferenceResult`,
which is produced by reference semantics over the parsed spec model.

4. Suites must not directly assert:

```text
compile success
compile failure
diagnostic code
diagnostic severity
runtime output
exit code
IR string
object artifact path
trace label
```

Suites may only select cases, request reference derivation, invoke implementation
execution, and pass both results to the comparator.

5. String matching over the raw spec is allowed only in the spec parser/scanner layer
and parser self-tests. It is forbidden as a source of expected behavior in
`Reference`, `Compare`, `Suites`, and `Coverage`.

6. Diagnostic codes and severities must be parsed from the spec diagnostic tables.
They must not be manually duplicated into compare tables.

7. Rule labels may identify parsed obligations, but a label alone is never evidence
of conformance.

8. Fixtures are test inputs, not truth. A fixture may reference an obligation id, but
it may not define the expected result.

9. The previous incorrect oracle implementation must be deleted before recreating
`CursiveOracle`.

10. No directories, files, cases, or symbols named:

```text
Migration
MigrationCase
migration_case
Imported
HelloCursive import
```

11. No PowerShell tool duplicates. If tooling is needed, prefer Python for
orchestration, but non-Cursive tooling must not encode conformance semantics.

12. Do not edit `docs/CursiveSpecification.md`.

13. Do not edit `docs/audit`.

14. A runnable fixture harness before the formal spec model exists is considered a
failed implementation.

15. A global conformance result must be impossible until the coverage ledger proves
every required spec obligation is handled.

16. Do not create placeholder files, empty module buckets, TODO-only stubs, or
`not implemented` scaffolding to simulate progress. A directory may be created only
when it receives at least one purpose-bearing file in the same task. A `.cursive`
file may be created only when it defines real data, parsing, reference, comparison,
runner, or reporting behavior required by the current phase.

## 6. What Must Not Be Built

Do not build any of these, even temporarily:

```text
A fixture runner whose expected outcomes are manually encoded.
A suite that directly checks compile success/failure.
A compare table mapping rule label -> diagnostic code.
A reference layer based on containsText over raw spec.
A coverage counter based on counting labels or strings.

A HelloCursive import bridge.
A migration/import compatibility layer.
A stub skeleton that claims phase completion because files exist.
```

If the current compiler cannot support a required oracle construct, record a blocker
and continue only with independent tasks that preserve the final architecture. Do not
replace the required construct with string matching or hard-coded expectations.

```text
CursiveOracle exists as a clean Cursive project.

Fixtures do not encode expected behavior.
The compiler/runtime under test is invoked independently.

ComparisonResult compares ReferenceResult to ImplementationResult.
CoverageLedger reports every required spec obligation.
Negative controls prove the oracle cannot rubber-stamp itself.
```

## 9. Execution Order Summary

```text
delete old oracle

build reference semantics
build case generator
build implementation runner
build comparator
add suites as thin orchestration
add negative controls

run verification
```

The incorrect order is:

```text
create fixtures
```

That path is explicitly rejected by this plan.
